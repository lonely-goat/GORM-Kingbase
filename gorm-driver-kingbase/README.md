# GORM KingbaseES Dialector

独立的 GORM v2 方言，底层使用 `kingbase.com/gokb`，支持 KingbaseES 的 MySQL、Oracle 两种兼容模式，通过 Dialector、Clause Builder、Callback 和 Migrator 扩展 GORM。

第一次读源码或接着维护时，先看[维护导读](docs/维护导读.md)，按问题定位文件和测试入口。

| 项目 | 当前配置 |
|---|---|
| Go 模块 | `kingbase.com/gorm-driver-kingbase` |
| 最低语言版本声明 | Go 1.22 |
| GORM 依赖与回归基线 | `gorm.io/gorm v1.31.1` |
| gokb | `v0.0.0`，通过 `../third_party/gokb` 引用随仓库保留的配套源码 |
| 已有实库验证环境 | Linux amd64、Go 1.26.2、KingbaseES V009R001C010 双模式 |

最低语言版本声明与已完成验证的工具链不同。其他数据库、驱动或工具链版本组合需要分别验证。

## 接入

下载完整交付仓库并保留 `gorm-driver-kingbase/` 与 `third_party/gokb/` 的相对位置即可构建，不再引用开发机上的外部 SDK 目录。推荐从[仓库根目录说明](../README.md)运行统一测试入口。业务项目作为依赖引用本模块时，按[开发与交付说明](docs/development.md)配置本地模块替换。

```go
package main

import (
    "log"
    "os"

    "gorm.io/gorm"
    kingbase "kingbase.com/gorm-driver-kingbase"
)

type User struct {
    ID   uint   `gorm:"primaryKey"`
    Name string `gorm:"size:128;not null"`
}

func main() {
    db, err := gorm.Open(kingbase.Open(os.Getenv("KINGBASE_DSN")), &gorm.Config{})
    if err != nil {
        log.Fatal(err)
    }
    sqlDB, err := db.DB()
    if err != nil {
        log.Fatal(err)
    }
    defer sqlDB.Close()

    if err := db.AutoMigrate(&User{}); err != nil {
        log.Fatal(err)
    }
}
```

`Open` 默认在初始化期间执行一次 `SHOW database_mode`。需要指定模式、注入连接池或调整探测超时时，使用 `New(Config{...})`：

```go
db, err := gorm.Open(kingbase.New(kingbase.Config{
    DSN:  dsn,
    Mode: kingbase.ModeOracle,
}), &gorm.Config{})
```

显式模式跳过探测，由调用方保证与实例一致。离线构建 SQL 还需配置自动 Ping、默认事务和连接池，单独设置 DryRun 不保证整个调用过程不访问数据库。

## 适配内容

| 功能 | MySQL 模式 | Oracle 模式 |
|---|---|---|
| 参数占位符 | `?` | `:1`、`:2` |
| 标识符引用 | 反引号 | 双引号 |
| 查询分页 | `LIMIT/OFFSET` | `OFFSET/FETCH` |
| 自增列 | 有符号整数 + `AUTO_INCREMENT` | 整数 + `GENERATED BY DEFAULT AS IDENTITY` |
| 生成主键回填 | `INSERT … RETURNING` 结果集 | 同左 |
| 字段类型 | boolean、整数、decimal、varchar/text、datetime、二进制等 | boolean、整数、NUMBER、VARCHAR2/CLOB、TIMESTAMP、BLOB 等 |
| 结构管理 | 复用 AutoMigrate，适配表、列、约束、索引和注释 | 同左，按模式生成 DDL |
| 元信息 | 结合 `information_schema` 和 `pg_catalog`，按 schema 定位 | 同左，单独处理 identity 和名称规则 |
| 错误转换 | SQLSTATE 23505、23503、23514、42703 | 同左 |

GORM 会话、模型解析、CRUD 编排、软删除、事务和关联引擎继续使用原框架。专用代码处理数据库差异，详见 [按七项功能的源码对照](docs/GORM-v2-KingbaseES代码修改说明-按七项功能.md)。

## 使用边界

- MySQL 模式 DSN 不应开启 `get_last_insert_id=yes`；它可能让 gokb 重复追加 RETURNING。可读取 DSN 的冲突配置会被初始化检查拒绝。
- `uint` 映射到有符号整数物理列，不覆盖完整无符号数值范围。
- MySQL 未声明精度的时间字段映射为 `datetime(3)`；`precision:0` 保留整秒。Oracle 时间字段使用带时区 TIMESTAMP，并保留显式精度。
- 时间行为取决于进程、连接及列的约定。已有官方回归使用进程 `TZ=UTC` 和 DSN `TimeZone=UTC`；其他时区需单独核对。
- Oracle 空字符串语义受 `ora_input_emptystr_isnull` 控制。方言不修改实例默认值；部分官方测试需要明确选用 `off`。
- Oracle 名称映射遵循测试实例中“全大写引用名称折为小写、混合大小写保留”的行为。无模型 Raw 查询应明确别名或 MapColumns。
- MySQL 冲突忽略、显式目标及条件保留 ON CONFLICT；无目标且无条件的更新使用 ON DUPLICATE KEY UPDATE。Oracle 无目标更新只在唯一候选键可推断时补齐。
- 无显式排序的 Oracle 分页会补主键或 ORDER BY 1；稳定业务分页仍需显式唯一排序。
- 常规 map 批量 RETURNING 归并排除 OnConflict 场景。
- `Has*` 和 `CurrentDatabase` 尚未完整向调用方传递查询错误，元信息故障时不能宣称 AutoMigrate 已统一阻断后续 DDL。已有表新增 unique 列等场景可能需要显式补建约束。
- 同一连接或事务中的活跃结果集应顺序消费并及时关闭；同一模型的 AutoMigrate 应串行执行。
- 开启 TranslateError 后，已识别 SQLSTATE 直接转换成 GORM 标准错误，不保留原始 gokb.Error 链；未知错误原样返回。

## 运行配置

- 两个实例分别监听本机 54321（MySQL）和 54322（Oracle），各自新建专用数据库运行自有集成与官方回归，没有复用现有业务数据库。
- MySQL 实例保持 `enable_ci=on`；Oracle 实例保持 `enable_ci=off`。两者均使用 UTF8。
- 自有集成测试保留 Oracle 的默认 `ora_input_emptystr_isnull=on`，通过的结果覆盖这一默认设置。
- 官方 Oracle 回归按既有文档约定，仅在测试连接上使用 `ora_input_emptystr_isnull=off`，以匹配相应上游用例的空字符串预期。
- 测试进程为 `TZ=UTC`，DSN 为 `TimeZone=UTC`；MySQL 使用 `get_last_insert_id=no`。
- 测后重新查询默认配置，两个实例的默认时区仍为 Asia/Shanghai，Oracle 的默认空字符串设置仍为 on，没有修改实例默认值。
- 密码通过测试子进程环境提供，没有写入源码或验证记录。

## 本轮发现并修复的测试问题

首轮自有测试为 34 个顶层测试通过、1 个失败；失败位于 Oracle 部分索引测试的无注释场景。

原测试以 `COALESCE(obj_description(...), '')` 扫描到普通 `string`。Oracle 默认将空字符串视为 NULL，因而该查询仍可能返回 NULL，触发扫描错误。

[索引回归测试](../integration/index_boundaries_test.go)已改为直接读取目录原值，使用 `sql.NullString`，同时断言有效性与内容。部分索引谓词、唯一性、重复插入及重复迁移断言仍保留。修复后先跑定向回归，再跑完整双模式集成及 GORM 回归，均无失败。适配器生产代码和 gokb 源码未修改。

## 复现与交付说明

在完整 Git 工作目录中，按[根目录 README](../../README.md)配置自己的两条专用测试库 DSN，然后执行：

```sh
KINGBASE_TEST_ALLOW_DDL=yes bash scripts/test.sh integration -race
KINGBASE_TEST_ALLOW_DDL=yes bash scripts/test.sh official-mysql
KINGBASE_TEST_ALLOW_DDL=yes bash scripts/test.sh official-oracle
```

复现官方 Oracle 结果时，DSN 需按[测试说明](testing.md)明确添加 `ora_input_emptystr_isnull=off`。不同实例设置、SDK、GORM 或 Go 版本组合需要分别验证。

此文是一次固定配置下的结果快照。后续源码更新后，应重新记录实际测试结果，不沿用本次计数。完整本机日志与首轮失败记录保存在开发工作区的 `test-results/dual-mode-2026-11-02-173852/`，该目录未随源码上传。
